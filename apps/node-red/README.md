# Node-RED

Node-RED is a visual, event-driven programming environment for connecting devices, APIs and services. This setup runs one authenticated editor with persistent flows, installed nodes and encrypted credentials.

## Supported setup

- Official Node-RED `5.0.9-24` image: Node-RED 5.0.9 on Node.js 24.
- Password-protected editor and Admin API through a tracked `settings.js`.
- Explicit credential secret so encrypted flow credentials remain recoverable across container recreation.
- Docker-managed `/data` volume by default and browser access bound to localhost.
- Optional shared-network extension for separately managed applications such as Mosquitto or PostgreSQL.

The image is pinned to an exact Node-RED and Node.js combination because runtime and contributed-node compatibility can change independently. Review both versions during an upgrade.

## Before you start

- Docker Engine and the Docker Compose plugin (`docker compose`).
- OpenSSL for generating the credential secret.
- An editor username and bcrypt password hash.
- Existing users: the legacy file used `/opt/docker/nodered/data` and Node-RED's generated credential key. Point `NODE_RED_DATA_SOURCE` at that directory before recreating it. Find and preserve the existing `credentialSecret` or generated key before setting a different one, otherwise saved node credentials may no longer decrypt.

Flows and contributed nodes can make network requests, access mounted files and execute code. Treat editor access as privileged, review imported flows and palette packages, and never mount the Docker socket or broad host directories into this container.

## Quick start

`.env` is required because editor authentication and credential encryption have no safe defaults:

```bash
cd apps/node-red
cp .env.example .env

# Put this output after NODE_RED_CREDENTIAL_SECRET= in .env.
openssl rand -hex 32

# Enter the editor password when prompted. Copy the resulting bcrypt hash.
docker run --rm -it --entrypoint node-red \
  nodered/node-red:5.0.9-24 admin hash-pw
```

Set `NODE_RED_ADMIN_USER` and put the hash after `NODE_RED_ADMIN_PASSWORD_HASH=`. Enclose the hash in single quotes so its dollar signs remain literal:

```dotenv
NODE_RED_ADMIN_PASSWORD_HASH='$2b$08$replace_with_complete_generated_hash'
```

Then start Node-RED:

```bash
docker compose config
docker compose up -d
docker compose ps
```

Open <http://localhost:1880> and sign in. For a remote Docker host, use an SSH tunnel:

```bash
ssh -N -L 1880:127.0.0.1:1880 user@server
```

Create an Inject → Debug flow, deploy it and confirm the message appears. Restart the container and verify the flow remains and can run again.

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `NODE_RED_CREDENTIAL_SECRET` | Required | Encrypts credentials stored with flows and must remain stable and secret |
| `NODE_RED_ADMIN_USER` | Required | Editor and Admin API login name |
| `NODE_RED_ADMIN_PASSWORD_HASH` | Required | Bcrypt hash generated by Node-RED, not the plaintext password |
| `NODE_RED_TIME_ZONE` | `Etc/UTC` | Container time zone using an IANA name |
| `NODE_RED_BIND_ADDRESS` | `127.0.0.1` | Host interface accepting editor and HTTP-node connections |
| `NODE_RED_PORT` | `1880` | Node-RED port on the Docker host |
| `NODE_RED_NODE_OPTIONS` | `--max-old-space-size=512` | Node.js runtime options, including its heap ceiling in MiB |
| `NODE_RED_ENABLE_PROJECTS` | `false` | Enables Git-backed Node-RED Projects in the editor |
| `NODE_RED_DATA_SOURCE` | `data` | Named volume or absolute host path for persistent runtime data |
| `SHARED_NETWORK_NAME` | `stacklab-shared` | Existing network used only by the shared-network extension |

The `.env` file contains the flow-credential decryption secret. Keep it out of Git, restrict access and include it in encrypted backups. Changing the editor password hash does not change the credential secret.

> [!WARNING]
> Changing the data source does not move flows, installed nodes, projects or credentials. An empty source starts a new instance. Back up first and inspect the resolved `/data` mount with `docker compose config`.

### Projects

Set `NODE_RED_ENABLE_PROJECTS=true` before startup to enable Node-RED Projects. Each project can have its own Git history, but Git is not a replacement for backing up the whole `/data` directory and credential secret. Configure Git identity and remotes through Node-RED according to upstream guidance.

## Shared-network extension

The extension lets Node-RED reach other Stacklab apps by Compose service name while preserving its private project network:

```bash
docker network create stacklab-shared
docker compose -f compose.yaml -f extensions/compose.shared-network.yaml up -d
```

Use the same file arguments for every lifecycle command. For example, with Mosquitto's matching extension enabled, configure the MQTT broker host as `mosquitto` and port `1883`. Authentication is still required. Home Assistant uses host networking in this repository, so reach it through the Docker host's LAN address rather than this shared network.

The shared network also makes port `1880` reachable to attached containers. Editor authentication remains mandatory. Install and maintain only the palette nodes required by your workflows.

## HTTP endpoints and reverse proxies

Editor authentication protects the editor and Admin API only. It does **not** automatically protect routes created with HTTP In nodes. Design authentication and authorization for each workflow endpoint.

A reverse proxy can connect through the shared-network extension. It must support WebSocket upgrades and provide HTTPS before any internet exposure. Keep the host port on loopback and follow [shared reverse-proxy guidance](../../docs/reverse-proxy.md) plus the [Node-RED security guide](https://nodered.org/docs/user-guide/runtime/securing-node-red).

## Your data

| Source | Container path | Contents | Backup need |
|---|---|---|---|
| `NODE_RED_DATA_SOURCE` | `/data` | Flows, encrypted credentials, installed nodes, projects and runtime settings | Essential |
| `./config/settings.js` | `/data/settings.js` | Tracked authentication and project configuration | Reproducible from Git |
| `.env` | Compose host only | Credential secret, editor identity and password hash | Essential and secret |

The read-only settings file overrides any `settings.js` inside the data volume. Named storage survives `docker compose down`. **`docker compose down -v` deletes it**.

## Back up and restore

Follow the [backup and restore guide](docs/backup-and-restore.md). Keep the `/data` archive and matching `.env` together. The flow credential file cannot be recovered with a different credential secret.

## Update

Back up first and read both the [Node-RED releases](https://github.com/node-red/node-red/releases) and [container releases](https://github.com/node-red/node-red-docker/releases). Change the pinned image tag in `compose.yaml`, then:

```bash
docker compose pull node-red
docker compose up -d
docker compose ps
```

Verify login, deployment, representative contributed nodes and credential-dependent connections. Review the Node.js version when native palette modules are installed. Restore the matching pre-update backup and image when rollback is required.

## Recovery and troubleshooting

| Symptom | Check / action |
|---|---|
| Compose reports missing values | Fill all required `.env` entries and keep the bcrypt hash single-quoted. |
| Login always fails | Generate a fresh bcrypt hash with `node-red admin hash-pw`, update only the password-hash value and recreate the container. |
| Nodes report undecryptable credentials | Restore the exact credential secret that encrypted the current flow credentials. |
| A bad flow causes repeated failures | Start temporarily in safe mode using the procedure below, fix and deploy the flow, then restart normally. |
| Bind-mounted data is not writable | Ensure host files are writable by container UID/GID `1000`. Do not solve this with world-writable permissions. |
| Another container cannot connect | Enable the same external network for both apps and use the target app's Compose service name. |

Safe-mode recovery stops normal flow execution while keeping the editor available:

```bash
docker compose stop node-red
docker compose run --rm --service-ports \
  -e NODE_RED_ENABLE_SAFE_MODE=true node-red
```

After repairing and deploying the flow, stop the foreground recovery container and run `docker compose up -d` normally. For general commands, see [shared troubleshooting](../../docs/troubleshooting.md).

## About this setup

The earlier files published the editor broadly and used a fixed container name, a machine-specific `/opt` path and a required external network. The current deployment adds editor security and a stable credential-encryption secret without forcing specific integrations into the base app.
